## 1. Intent & Problem Framing

### 1.1 Root problem
Hệ thống đã trải qua tái cấu trúc lớn trên 5 trục đồng thời (Vox-Style narrative, 7-account Google Flow pool, Critic Council, Remotion post-prod, Prompt 2/3/4 decoupled). Tái cấu trúc đa trục song song luôn sinh ra một lớp bệnh lý đặc trưng:

| # | Lớp lỗi | Biểu hiện | Hệ quả |
|---|---|---|---|
| F1 | **Contract drift** | Mỗi stage tự định nghĩa shape JSON; stage N+1 đọc key không còn tồn tại (`scenes` vs `shots` vs `segments`) | Pipeline vỡ giữa chừng, mất run |
| F2 | **Path entropy** | Hardcode path, mix absolute/relative, mỗi stage tự quyết `output_dir` | Artifact "mất tích", stage sau không thấy input |
| F3 | **Ghost code / bypass** | Module cũ vẫn import được, vẫn có `__main__`, orchestrator cũ vẫn chạy | Dev/agent vô tình chạy luồng cũ → kết quả sai mà không báo lỗi |
| F4 | **Boundary blindness** | Không có validation gate giữa các stage | Lỗi phát hiện ở stage 7 nhưng nguyên nhân ở stage 2 |
| F5 | **Decoupling nửa vời** | Prompt 2/3/4 tách file nhưng vẫn share state ngầm (global config, cached dict, implicit ordering) | Chạy lẻ 1 stage thì fail, chỉ chạy full mới pass |
| F6 | **Pool state race** | 7-acc rotation ghi state không atomic, không phân biệt quota-exhausted vs transient-fail | Treo pipeline, hoặc đốt account |
| F7 | **Mock leakage** | Fixture/stub dùng để test refactor còn sót trong code path production | "Chạy được" nhưng video rỗng/giả |
| F8 | **Remotion props mismatch** | TS props type và Python output JSON lệch nhau, không có single source of truth | Render fail hoặc render ra frame trống |

### 1.2 Trade-off quyết định

**TO-1: Sửa tại chỗ (patch từng lỗi) vs Dựng lớp contract rồi ép tuân thủ.**
→ **Chọn: dựng lớp contract.** Patch từng lỗi là vòng lặp vô tận đúng như user mô tả ("gián đoạn sửa lỗi"). Chi phí một lần cho `core/contracts` + validation gate sẽ biến lỗi runtime ngẫu nhiên thành lỗi deterministic tại biên, fail fast với message chỉ đúng stage sai.

**TO-2: Xoá code cũ vs Quarantine.**
→ **Chọn: Quarantine có import-guard, KHÔNG xoá ngay.** Xoá ngay sẽ mất reference logic nghiệp vụ (prompt wording, heuristic rotation) chưa chắc đã port hết. Quarantine = di chuyển vào `legacy/`, chèn import-guard raise lỗi khi bị gọi từ runtime, cộng CI deny-list. Lịch xoá thật: sau khi E2E xanh 3 run liên tiếp (Phase 8).

**TO-3: Pydantic strict vs dict mềm dẻo.**
→ **Chọn: Pydantic v2 `model_config = ConfigDict(extra="forbid")` ở biên stage.** Dict mềm dẻo chính là nguyên nhân F1. `extra="forbid"` bắt ngay key rác/key đổi tên.

**TO-4: Validation gate blocking vs warning.**
→ **Chọn: blocking, có `--force` escape hatch ghi log WARN rõ ràng.** Mục tiêu của user là "mượt mà A→Z"; mượt mà thật = không bao giờ chạy tiếp trên dữ liệu rác.

### 1.3 Critical considerations
- **Không được phá run đang có.** Mọi artifact cũ phải đọc được qua `legacy_adapter` một chiều (read-only migration), không ngược lại.
- **Idempotency & resume.** Pipeline tốn tiền (Veo generation). Mọi stage phải skip-if-valid-artifact-exists, resume từ stage fail.
- **Zero-Mock (Rule 127).** Verification cuối cùng phải là một run thật, tạo file video thật trên đĩa, exit code 0.
- **Cost control.** Venue OFFLINE_LOCAL nên không chạm quota VPS API, nhưng E2E thật có đốt Veo quota → dùng profile `e2e_min` (1 scene, 1 shot, độ dài tối thiểu).

### 3.1 Lớp nền mới (CREATE)

#### `core/paths.py` — single path authority
Diệt F2. Mọi stage **cấm** tự ghép path.

class RunPaths:
    """Duy nhất một nơi quyết định artifact nằm đâu."""
    root: Path                 # <REPO>/runs/<run_id>/
    manifest: Path             # root/run_manifest.json
    def stage_dir(self, stage: StageID) -> Path   # root/<NN>_<stage_name>/
    def artifact(self, stage: StageID) -> Path    # stage_dir/artifact.json

#### `core/contracts/__init__.py` + `core/contracts/stages.py` — schema contracts
Diệt F1. Pydantic v2, `extra="forbid"`, có `schema_version`.

```python
SCHEMA_VERSION = "1.0.0"

class StageID(str, Enum):
    S1_IDEATION=...; S2_RESEARCH=...; S3_SCRIPT=...; S4_CRITIC_SCRIPT=...
    S5_SHOTLIST=...; S6_CRITIC_VISUAL=...; S7_VIDEO_GEN=...
    S8_VOICE=...; S9_ASSEMBLY=...; S10_RENDER=...; S11_QC=...

class StageArtifact(BaseModel):            # envelope chung
    model_config = ConfigDict(extra="forbid")
    schema_version: str
    run_id: str
    stage: StageID
    created_at: datetime
    status: Literal["ok","partial","failed"]
    payload: <stage-specific>
    provenance: Provenance                 # model, prompt_id, cost, latency

# Payload cốt lõi (CANONICAL VOCABULARY — chốt một lần, cấm biến thể)
class Scene(BaseModel):                    # đơn vị narrative (Vox-style beat)
    scene_id: str                          # "sc_001"
    beat_role: Literal["hook","context","tension","reveal","payoff","outro"]
    narration: str                         # text đọc, đã final
    duration_sec: float
    shots: list[Shot]

class Shot(BaseModel):                     # đơn vị generation
    shot_id: str                           # "sc_001_sh_01"
    visual_prompt: str                     # prompt gửi Google Flow
    negative_prompt: str | None
    duration_sec: float
    aspect: Literal["16:9","9:16","1:1"]
    continuity_ref: str | None              # shot_id tham chiếu để giữ nhất quán

class VideoAsset(BaseModel):
    shot_id: str; file: Path; account_slot: int
    attempt: int; sha256: str; duration_sec: float

class CriticVerdict(BaseModel):
    critic_id: str; score: float            # 0..10
    verdict: Literal["pass","revise","reject"]
    issues: list[CriticIssue]

class CouncilDecision(BaseModel):
    verdict: Literal["pass","revise","reject"]
    aggregate_score: float
    round: int
    verdicts: list[CriticVerdict]
    revision_directives: list[str]          # input cho stage re-run
```
> **Quyết định từ vựng chuẩn:** `Scene` (narrative) ⊃ `Shot` (generation). Mọi tên khác đang tồn tại (`segment`, `clip`, `beat`, `shotlist_item`) phải map về đây trong Phase 2 và biến mất khỏi runtime.

## 4. Step-by-Step Task Decomposition (Worker: Gemini 3.8 Flash High)

> Quy ước: mỗi task có **IN** (đầu vào cụ thể), **OUT** (artifact cụ thể), **DONE** (điều kiện kiểm chứng được). Worker **không được** nhảy task. Sau mỗi Phase phải chạy gate verification của Phase đó.

### PHASE 0 — DISCOVERY (read-only, KHÔNG sửa code)

**T0.1 — Repo inventory**
IN: repo root.
OUT: `reports/00_inventory.json` + `.md` gồm: cây thư mục (depth 4), mọi file `.py/.ts/.tsx/.yaml/.json` kèm LOC, mtime, có `__main__` hay không.
DONE: file tồn tại, số file > 0, JSON parse được.

**T0.2 — Import graph & entrypoint map**
IN: toàn bộ `.py`.
OUT: `reports/01_import_graph.json` (node = module, edge = import), `reports/01_entrypoints.md` (mọi `if __name__ == "__main__"`, mọi script trong `scripts/`, mọi console_script trong `pyproject.toml`).
DONE: liệt kê đầy đủ entrypoint; đánh dấu entrypoint nào **không** reachable từ orchestrator mới.

**T0.3 — GHOST candidate detection** (cốt lõi anti-ghost)
IN: T0.1, T0.2.
OUT: `reports/02_ghosts.md` — bảng: `file | lý do nghi ngờ | in-degree | có __main__ | last_mtime | verdict(GHOST/ACTIVE/UNSURE)`.
Heuristic: in-degree = 0 và không phải entrypoint chính thức; hoặc tên trùng/biến thể (`*_old`, `*_v1`, `*_bak`, `*_new`, trùng tên hàm ở 2 nơi); hoặc chứa logic prompt mà orchestrator mới không gọi.
DONE: mọi file có verdict; `UNSURE` ≤ 10% và được liệt kê riêng để người duyệt.

**T0.4 — Schema drift matrix** (cốt lõi anti-drift)
IN: toàn bộ code đọc/ghi JSON + mọi artifact mẫu trong `runs/`.
OUT: `reports/03_schema_drift.md` — bảng cho từng biên stage: `producer file:line | key xuất | consumer file:line | key kỳ vọng | DRIFT?`. Kèm danh sách từ vựng trùng nghĩa phát hiện được (`scenes|segments|shots|clips|beats`).
DONE: liệt kê ≥ 1 dòng cho mỗi biên trong §3.0; mọi DRIFT có mã `D-xxx`.

**T0.5 — Path audit**
IN: grep toàn repo.
OUT: `reports/04_paths.md` — mọi hardcode path, mọi `os.path.join`/f-string path, mọi absolute path, mọi nơi tự tạo `output_dir`. Mỗi dòng gắn mã `P-xxx`.
DONE: không còn pattern path nào chưa phân loại.

**T0.6 — Mock leakage + venue classification**
IN: grep `mock|fake|stub|dummy|sample|TODO|FIXME|placeholder|lorem`; grep `while True|schedule|cron|APScheduler|telegram|webhook|polling`.

IN: entrypoint hiện tại.
OUT: `reports/08_baseline_run.md` — chạy pipeline hiện tại ở cấu hình nhỏ nhất, ghi lại stage nào fail, traceback đầy đủ, exit code.
DONE: có kết quả thật (kể cả fail). **Không** được bỏ qua bằng cách đoán.

**T0.8 — Issue register hợp nhất**
OUT: `reports/ISSUES.md` — gộp `D-*`, `P-*`, `M-*`, ghost, baseline failure thành bảng: `id | class(F1..F8) | severity(S1 blocker/S2 major/S3 minor) | file | fix phase | trạng thái`.
DONE: mọi issue có `fix phase`. Đây là **backlog chính thức**, mọi task sau phải tick vào đây.

## 5. Strict Verification Protocol & Acceptance Criteria

### 5.1 Rule 127 — Zero-Mock (bắt buộc tuyệt đối)
- Verification cuối cùng **phải** là một run thật gọi API thật, sinh file thật trên đĩa. Không chấp nhận mock, không chấp nhận "logic đã đúng nên sẽ chạy được".
- `AVF_ALLOW_MOCK=1` **chỉ** được set bởi pytest; nếu biến này xuất hiện trong bất kỳ profile/CI prod → fail.
- Fixture test phải lấy từ artifact run thật (`runs/`), không bịa dữ liệu.
- Nếu một bước thật sự không thể chạy (thiếu credential, hết quota), worker **phải** báo `BLOCKED` kèm lý do cụ thể và output lỗi nguyên văn. **Cấm** báo done.

### 5.4 Quy tắc báo cáo của Worker
- Sau mỗi Phase: báo `GATE <n>: PASS/FAIL` kèm output lệnh **nguyên văn** (có dòng `EXIT=`).
- Cấm tự ý nhảy Phase khi gate FAIL. FAIL → sửa, chạy lại gate, rồi mới tiếp.
- Cùng một lỗi fail 2 lần theo cùng cách tiếp cận → **dừng tweak**, viết chẩn đoán nguyên nhân gốc vào `reports/ISSUES.md` và đổi hướng tiếp cận, báo lại người dùng nếu hướng mới lệch khỏi kế hoạch này.
