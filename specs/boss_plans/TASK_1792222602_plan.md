# IMPLEMENTATION PLAN: E2E VIDEO AI PIPELINE AUDIT & RESILIENCE HARDENING

## 1. INTENT & PROBLEM FRAMING

### Root Problem
The AI Video Factory pipeline spans 11 stages (ideation → QC) with handoffs between VPS automation, local IDE development, and git synchronization. Critical vulnerabilities exist:

- **Stuck/Hanging Risk**: Stage transitions may block indefinitely if state markers are inconsistent or file locks aren't released
- **Token Leakage**: Redundant LLM calls due to missing cache checks, retry loops without exponential backoff, or parsing failures that trigger re-generation
- **Crash/Recovery Gap**: Unhandled exceptions in image_gen (s07) or video_gen (s08) may leave projects in limbo without rollback or resume capability
- **Over-Credit Risk**: External LLM APIs (Claude/Gemini) invoked without cost gates, quota exhaustion handling, or fallback to cheaper models
- **Human Gate Ambiguity**: Unclear contract on when automation pauses for approval vs. when it auto-proceeds

### Trade-offs
- **Audit Depth vs. Speed**: Comprehensive code tracing across VPS + local + git requires reading ~50+ files; prioritize critical bottlenecks (s07/s08/s10 render)
- **Automatic Recovery vs. Data Integrity**: Aggressive auto-retry may corrupt intermediate artifacts; manual gates slow throughput but ensure quality
- **Cost vs. Reliability**: Aggressive caching reduces LLM costs but risks stale content; real-time regeneration ensures freshness but burns tokens

### Critical Considerations
- **State Synchronization**: VPS scheduler (cron/systemd) must reconcile with local IDE state via git; race conditions possible if both modify project JSON simultaneously
- **Credit Budget Enforcement**: Must verify `budget_manager.py` or equivalent enforces hard caps per project/per stage
- **Human Approval Points**: Identify exact stages requiring `human_approval: true` flag vs. auto-proceed
