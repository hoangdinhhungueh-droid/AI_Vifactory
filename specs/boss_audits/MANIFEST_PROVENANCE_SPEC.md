# Architecture Decision Record (ADR): Dual-Tier Manifest Provenance & Evidence Lifecycle

**Specification ID**: `ADR-MANIFEST-PROVENANCE-001`  
**Governing Rules**: `Rule 121 (Verification Protocol)`, `Rule 125 (Single Truth & Zero Ghosts)`, `Rule 126 (Three-Way Parity)`  
**Status**: `APPROVED & COMMITTED ARCHITECTURAL STANDARD`  
**Applicability**: All Episode Audits under Boss Supervisory Gate (`TASK_1792314467` / `JP_TEMP_59` and successors)  

---

## 1. Problem Statement & The "Git Observer Effect"

In cryptographic code verification, an inescapable mathematical constraint arises when attempting to store live post-commit execution evidence inside the same tracked repository:
1. **The Circular Mutation Trap**: If an orchestrator records dynamic execution timings, live CI workflow run IDs (e.g., GitHub Actions `run_id`), or post-HEAD evidence bundle digests directly into a tracked Git file, that write mutates the working tree (`git status --porcelain` becomes dirty).
2. **Invalidated Tree Hash**: Committing this modified file generates a *new* commit SHA (`HEAD' != HEAD`), which invalidates the previously executed CI run, changes the git tree hash, and destroys the three-way physical parity guaranteed by Rule 126.
3. **The Clean Working Tree Mandate**: Rule 126 strictly mandates zero dirty porcelain on all nodes (`Local Windows ⇄ Linux VPS ⇄ GitHub Origin Main`). Therefore, tracked files cannot be modified after commit without violating Rule 126.

To resolve this without circular mutation or false claims of identity, the AI Video Factory formally adopts the **Dual-Tier Manifest Provenance Architecture**.

## 2. Two-Tier Verification Architecture

```
                  ┌─────────────────────────────────────────────────────────────┐
                  │                 GIT REPOSITORY (Tracked)                    │
                  │                                                             │
                  │  specs/boss_audits/{task_id}_manifest.json                  │
                  │  ├── Tier 1: Committed Pre-Audit Baseline Manifest          │
                  │  ├── Immutable Git Commit SHA & Tree Hash                   │
                  │  ├── Declared Verification Probe Set (13 Mandatory Gates)   │
                  │  └── Frozen Baseline Artifact Hashes                        │
                  └──────────────────────────────┬──────────────────────────────┘
                                                 │
                                                 │ Immutable Contract Binding
                                                 ▼
                  ┌─────────────────────────────────────────────────────────────┐
                  │            EVIDENCE BUNDLE (.gitignore Encapsulated)        │
                  │                                                             │
                  │  specs/boss_audits/{task_id}_evidence_bundle/               │
                  │  ├── manifest.json (Bit-for-bit identical copy)             │
                  │  ├── bundle_manifest.json (SHA-256 hash inventory)          │
                  │  ├── 20+ Physical Artifacts (.patch, .xml, logs, scripts)   │
                  │  └── post_head_attestation.json                             │
                  │       (Tier 2: Generated by Independent Verifier Subprocess) │
                  └─────────────────────────────────────────────────────────────┘
```

### 2.1 Tier 1: Committed Pre-Audit Baseline Manifest
- **File Location**: `specs/boss_audits/{task_id}_manifest.json`
- **Tracking Status**: Tracked in Git, committed into `HEAD`.
- **Authority**: Establishes the static baseline contract for the task. It immutably binds:
  * `head_commit_sha`: Exact 40-character commit SHA being audited.
  * `tree_sha`: Exact 40-character tree hash of the repository.
  * `cumulative_base_commit_sha`: Cumulative origin anchor (`517b082...`).
  * `incremental_delta_base_sha`: Pre-round delta anchor.
  * `probes`: Expected status and exit codes for all 13 verification probes.
  * `artifact_digests`: Hashes for zero-mock, service readiness, and AST scanners.

### 2.2 Tier 2: Post-Audit Live Evidence Bundle Manifest & Attestation
- **Location**: `specs/boss_audits/{task_id}_evidence_bundle/`
- **Tracking Status**: Gitignored (`git check-ignore specs/boss_audits/*_evidence_bundle/` returns code 0).
- **Authority**: Contains physical, retrievable proof artifacts generated during live test execution:
  * Incremental and cumulative unified diff patches.
  * Live GitHub Actions workflow run telemetry (`run_id`, `conclusion`, `html_url`).
  * Standalone Rule 139 AST scanner source (`ast_scanner_source.py`), version metadata, and raw execution output.
  * Raw JUnit XML test results for Linux VPS and Windows Local.
  * Service readiness structured cleanup failure telemetry.

## 3. Reconciliation Rules & Bit-for-Bit Identity Guarantee

To guarantee zero ambiguity and prevent intra-run divergence:
1. **Timestamp Determinism**: `aggregate_manifest` reuses the committed `verification_timestamp` whenever `head_commit_sha == git_head`. It NEVER mutates tracked porcelain during audit execution.
2. **Manifest Bit-for-Bit Parity**: `specs/boss_audits/{task_id}_evidence_bundle/manifest.json` is a bit-for-bit identical copy of `specs/boss_audits/{task_id}_manifest.json`. Their SHA-256 hashes MUST match 100%.
3. **Inventory Integrity**: Every artifact in the bundle directory is cryptographically inventoried in `bundle_manifest.json` with its exact size in bytes and SHA-256 digest.

---

## 4. Independent Verification Authority Protocol

To eliminate self-referential bias where an orchestrator attests to its own outputs:
1. **Decoupled Execution**: The post-HEAD attestation is NOT generated by inline strings in `boss_orchestrator.py`.
2. **Standalone Process**: It is generated by invoking `scripts/forensics/verify_bundle_post_head.py` as an external subprocess *after* all bundle files are finalized on disk.
3. **Independent Re-Hashing**: The verifier script independently:
   - Queries Git directly via low-level plumbing (`git rev-parse HEAD`, `git rev-parse HEAD^{tree}`).
   - Re-reads every file from disk and computes its SHA-256.
   - Cross-checks all computed hashes against `bundle_manifest.json`.
   - Records verifier PID and parent PID in `post_head_attestation.json`.
   - Returns exit code 0 only when all 7 verification gates pass.

---

## 5. Architectural Invariant

Future supervisory audits MUST treat this two-tier design as the official, permanent architectural standard. Discrepancies are defined strictly as:
- Any hash mismatch between root `manifest.json` and bundle `manifest.json`.
- Any hash mismatch between physical bundle files and `bundle_manifest.json`.
- Any untracked git mutation caused by audit execution.
The existence of Tier 1 (tracked baseline) alongside Tier 2 (gitignored physical bundle) is by design and certified permanent.
